# Agent failure modes in the audio-skeleton lineage, and the check that answers each

Shareable; no human wording (the human is cited as "human, 2026-10-02" only). Written 2026-10-02 by a subagent of main session `13236b40` (Claude, control plane). Purpose: the human decided to start from R1, drop the lineage's code and models whole while keeping its review as evidence ([d-restart-r1](evaluation-first.md#d-restart-r1)), and turn each thing the agents did wrong into a check that fails when it recurs ([evaluation-first, d-eval-first](evaluation-first.md#d-eval-first)). This file is the list of those things, with their evidence and the check. The checks are proposals; whether they are enforced in code or only as brief rules is open ([evaluation-first, open items](evaluation-first.md#open-for-the-human)).

Sources: the lineage review ([synthesis](lineage-review/synthesis.md), reviewer reports under [astra/](lineage-review/astra/) and [opus/](lineage-review/opus/), the [audit](lineage-review/fable/synthesis-audit.md)), the paraphrased [feedback index](audio-skeleton-human-feedback-index.md) (V numbers), and read-only reads of the lineage tag `audio-joint-2026-09` where cited as `audio-joint-2026-09:<path>`.

Strength is stated as the synthesis states it: **replicated** (two or more reviewers, independently, from code or artifacts), **single** (one reviewer, against code or artifacts), **doc** (read in a lineage document only), **audited** (recomputed or re-read by the auditor). One more label is used here: **human** means the pattern rests on the human's statement of 2026-10-02 and the review supplies no verified example. Each section separates what was observed, how it is read, and what is proposed.

Where the evidence qualifies a pattern as the human or the main thread stated it, the qualification is given under "Where the evidence narrows it" and is not softened.

## 1. Claimed, not done

<a id="fm-claimed-not-done"></a>**Failure mode, replicated and audited, 2026-10-02.** A component described as part of the system was not in the path that produced the output the human judged, and nothing in the report or the code tied the description to that path.

Observed:

- No time-horizon response scorer or planner was in the system the human played or that qualification scored; the demo server and the qualification runner build a plain `ControlledSession` directly (`audio-joint-2026-09:src/ensomi_model/research/gameplay_evaluation/qualification.py` lines 229 to 230), the planner lives in study scripts. A per-gap corpus-rarity preference was in that plain session by default, so the exact form is "the planner and the time-horizon scorers were absent; a single-gap penalty was present" ([s-response-not-in-loop](lineage-review/synthesis.md#s-response-not-in-loop); [audit](lineage-review/fable/synthesis-audit.md) C5 and S4; [opus/player-response](lineage-review/opus/player-response.md#1-summary) section 1; [astra/04](lineage-review/astra/04-player-response-frontier.md) item 4 of section 10, "planner available versus planner active"; [astra/08](lineage-review/astra/08-codex-interpretation.md) section 5 item 5: "never made familiar names guarantee the intended runtime role"). The human's problem G (twelve messages over five days) assumed the frontier was judging candidates ([index, section 3](audio-skeleton-human-feedback-index.md)).
- The final segment decoder accepts `local` and `timing` (the candidate-consequence inputs) and never reads them: `audio-joint-2026-09:src/ensomi_model/research/segment_audio_continuation/model.py` lines 159 to 174, both names in the signature and nowhere in the body (re-read for this file; [astra/08](lineage-review/astra/08-codex-interpretation.md) checked evidence D, checked-code and checked-artifact with a four-window lesion). Committed 09-28 12:54Z (`7d31b1e`); found by the agent at 17:14Z (`96f84fd`) after the human asked whether the models perceive elapsed time (index V80, V81).
- The inverse also occurred: the primary clean-joint document ends at 512 updates while the receipts show 4,096 for all three arms ([astra/08](lineage-review/astra/08-codex-interpretation.md) section 10 item 7). A report can under-claim as well as over-claim when it is not generated from receipts.
- The chart and seed the human played were not retained (index V47), so the first long-jack rejection cannot be replayed ([opus/evaluation](lineage-review/opus/evaluation.md#11-not-verified-and-how-to-follow-up) section 11).

Reading: the lineage's own code was careful about status (`promoted=false`, `review_required`), and the omissions were not hidden in prose; they were invisible because no artifact listed what ran. Claims about the system were made from the source tree, where the component existed, not from the generation path, where it did not.

Proposed check: an **execution receipt**, written by the generation entry point itself for every output, on every path the human uses (demo server, qualification, study scripts): entry point name, session class, every scorer, planner, guidance or preference object instantiated with its resolved config, checkpoint hash, resolved config, seed, output hash. The job launcher (`ens run`, `ens astra`) refuses to mark a job's report complete when an output it names has no receipt. A fresh read-only verifier matches each report sentence of the form "X is in the system" against the receipts' component lists; a component named in the report and absent from the receipt makes the claim fail. The demo path writes the same receipt and keeps the chart, so what the human plays is always replayable.

Cost, and what it cannot catch: instrumenting the entry points once; a receipt names code paths, so a component that is present and inert (the dead `local` and `timing` inputs) passes it; that case is [fm-tests-not-binding](#fm-tests-not-binding). It also cannot say whether the component did anything useful.

## 2. Tests that do not bind the claim

<a id="fm-tests-not-binding"></a>**Failure mode, human; the review supports a narrower form, 2026-10-02.** The lineage's tests verified the mechanism as written and were cited as evidence of readiness, but no test bound the claim an experiment reported, so a wrong claim left every test green.

Observed, from the review: no reviewer found the tests defective. [astra/07](lineage-review/astra/07-evaluation.md) ran 43 selected observer tests and passed them, calls them "synthetic regression tests" worth keeping (section 6), and says of the temporal observers that "tests establish additive/prefix semantics" with no quality threshold (section 2). [opus/player-response](lineage-review/opus/player-response.md#11-worth-keeping) section 11 lists the state machinery "with its tests" as worth keeping. [astra/01](lineage-review/astra/01-r1-foundation.md) records "implementation and engineering tests; no ... new generation recorded" for a 09-20 R1 step. The pattern as stated by the human has no verified example in the reports.

Observed, from the tag (read-only, bounded to five files): the lineage added 86 `test_*.py` modules under `tests/` to the baseline's 112 (198 at the tag). In its six main packages there are about 390 test functions and twelve shape assertions in total, so "tests asserting shapes" is not what happened. What did happen:

- `audio-joint-2026-09:tests/research/segment_audio_continuation/test_segments.py`, `test_single_code_restores_future_context_effect_and_joint_likelihood_gradients`, checks that gradients reach four parameter groups and that the plan-context input changes the row scores. No test lesions `local` or `timing`. The suite was green on a decoder that had dropped the consequence path, in the same commit (`7d31b1e`) that added both files.
- `audio-joint-2026-09:tests/research/gameplay_evaluation/test_qualification.py`: eight tests assert run statuses, file existence, gate names and `promoted=false` on synthetic runs; none asserts which session class the runner generates with. The property the human relied on, that the frontier judges candidates before publication, was never a tested property ([fm-claimed-not-done](#fm-claimed-not-done)).
- `audio-joint-2026-09:tests/research/controlled_audio_continuation/test_frontier.py`, `test_action_reference_can_publish_from_bos_without_an_unrequested_sentinel_scope`, builds a reference whose limits are 1,000 everywhere and asserts the first proposal is accepted; `audio-joint-2026-09:tests/research/gameplay_evaluation/test_ln_fragmentation.py`, `test_shortness_is_a_prevalence_coordinate_not_an_individual_ban`, asserts that a single 40 ms hold passes. Both restate a design decision. The first is the decision under which a real planner run accepted a 25 ms hold at zero work ([opus/player-response](lineage-review/opus/player-response.md#5-three-documented-failures-which-of-the-three-explanations-held) section 5, failure D); the second is the family of decision under which the 80 ms check passed all twelve V68 charts ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F4). A test cannot tell that the decision it enshrines is the defect.

Reading: "useless" is accurate about what the tests were used for (the baseline entry point's module table has a "Tests" column as its evidence of each module, and the lineage's documents cite test passes beside experiment results) and inaccurate as "trivial". The tests answer "does the code do what I wrote"; nothing answered "is what I wrote the claim". What would verify the human's stronger reading: a fresh reader codes a sample of the 86 files as mechanism-only, claim-binding or trivial; five were read here, all mechanism-only, none trivial.

Proposed check, four parts: (1) **claim test**: every claim in a report names the test or evaluator run that fails if the claim is false; the verifier labels a claim without one "untested", and the brief template asks for it before the run. (2) **Input-lesion test** for every model forward: for each named input, perturb it and assert the output changes, or document the input as unused in the same test; mechanical, one forward per input, run by the test suite and the pre-push skill. (3) **Evaluator tests carry witnesses**: each evaluator ships with at least one chart from the held-out failure set that must fail and one held-out ranked chart that must pass ([evaluation-first, Part 1 item 4](evaluation-first.md#p-chart-eval)), so a test that enshrines a blind spot fails when the failure set grows. (4) **Review rule**: the main thread, or a fresh reader, classifies each new test as mechanism-only or claim-binding; mechanism-only tests are engineering and are not cited as evidence for a result.

Cost, and what it cannot catch: lesion tests catch dead inputs, not inputs that are read and then ignored by trained weights (that needs the fit-time lesion the lineage did once, in its time-path probe); a claim test cannot exist for a claim with no metric, which is [fm-preconditions](#fm-preconditions).

## 3. Conclusions drawn before their preconditions were met

<a id="fm-preconditions"></a>**Failure mode, replicated, budgets audited, 2026-10-02.** Conclusions about architecture, initialisation and direction were drawn from runs that had not met the preconditions such a conclusion needs: training to a plateau, sane optimisation and support settings, a measured baseline, a measured noise floor.

Observed:

- The largest audio fit used 9% of one pass over the ranked corpus; the three-arm clean joint comparison 6.2%, its fresh arm still improving in likelihood, grid alignment and head F1 when it stopped; every other late run 32 to 512 updates; every logged gradient norm in the three arms above the clip; the 30 times slowdown that set the pilot sizes never profiled ([s-undertrained](lineage-review/synthesis.md#s-undertrained); [audit](lineage-review/fable/synthesis-audit.md) C6 and O2; [opus/proposal-recipe](lineage-review/opus/proposal-recipe.md#3-findings) F1, F2). The longest per-model training was about 1.6 h while the 35M teacher just before the lineage ran 23.7 h, so long runs were not ruled out by policy (F1).
- The fresh ordinary expert saw 64 s of chart from four songs for 512 updates with a support that allowed 1 ms holds; the human's reconsideration of the architecture on 09-29 rested on it (index V84, corrected in [index, section 5](audio-skeleton-human-feedback-index.md); [s-not-ordinary](lineage-review/synthesis.md#s-not-ordinary); [opus/proposal-recipe](lineage-review/opus/proposal-recipe.md#3-findings) F5, F7).
- Single short fits steered for days: one 23-minute, one-seed coverage run with a still-improving curve fixed the data regime for six days; four cells of 6 to 10 minutes set full-song audio aside for three days ([opus/interpretation](lineage-review/opus/interpretation.md#4-locality-and-turning-points-counted) section 4). The agent's own rule required a small fit to pass native quality before anything was scaled, and none ever did (section 2).
- No evaluator was run on R1 before building on it; with real times R1 already shows milder forms of complaints A and B ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F9; [s-r1-quality](lineage-review/synthesis.md#s-r1-quality)).
- The habit predates the lineage: the pre-V3 mapper was judged at half a pass ([opus/pre-v3-history](lineage-review/opus/pre-v3-history.md#8-lessons-recorded-before-v3-that-the-september-lineage-repeated) section 8).

Where the evidence narrows it: several small-pilot findings are structural and hold at any scale (a deleted path, a one-state code, all-TAP targets; [opus/proposal-recipe](lineage-review/opus/proposal-recipe.md#3-findings) F9), and the documents mostly hedged; [astra/08](lineage-review/astra/08-codex-interpretation.md) section 3 finds no source where the agent said a 32-update failure disproved an architecture. The error is in what was done next, not in the sentence written at the time ([v-pilot-scale](lineage-review/synthesis.md#v-pilot-scale)).

Proposed check: a **pre-registered stop rule and scale statement**. The brief states, before the run, the convergence criterion (validation plateau over a stated number of checkpoints, or a stated number of passes over the data), the seeds, the songs, and which kind of conclusion the run may support. The report's claim line carries updates, passes over data, seeds, songs, the share of gradient steps above the clip, and the support settings, all taken from the receipt and the loss log. The job launcher can test the plateau mechanically from the loss log. The verifier refuses a conclusion about architecture, initialisation or direction from a run below its stop rule; such a result is reported as "endpoint rejected at budget B" and nothing more. Structural findings are exempt and must cite the code line that shows them. Every comparison table carries the baseline rows ([evaluation-first, Part 1 item 5](evaluation-first.md#p-chart-eval)).

Cost, and what it cannot catch: longer runs on the mac, which is the budget question H9; a plateau under a bad recipe does not separate a recipe ceiling from a representation ceiling ([d-grid-cause](lineage-review/synthesis.md#d-grid-cause)); only scale as a controlled variable does that, and this check only makes the uncontrolled case say so.

## 4. Repair at the nearest module; questions recognised and not settled

<a id="fm-local-repair"></a>**Failure mode, replicated in direction, counts not reproducible, 2026-10-02.** After a failure the next action was usually a repair at the module nearest the symptom; upstream reconsideration mostly followed a human or expert message; questions the agent had itself recognised as open were not settled before the next step.

Observed: both reviewers of the trajectory find repeated repair at the symptom module, problems A and B outliving dozens of repairs, day-1 alternatives never tried, and correct diagnoses not acted on ([s-local-search](lineage-review/synthesis.md#s-local-search)). Put on one denominator, upstream moves mostly followed a human or expert message (12 of 13 in one coding, 10 to 12 of 19 in the other) and local moves were mostly the agent's (about 25 of 27; 10 of 14); the eight structural changes that held were all committed inside or within 80 minutes after a human message window; under a strict reading the agent started two upstream reconsiderations on its own in six days ([d-locality-counts](lineage-review/synthesis.md#d-locality-counts); [audit](lineage-review/fable/synthesis-audit.md) 3a). In the typed-skeleton episode the agent's own evidence located the ownership problem at 06:12Z and it repaired contracts inside the typed line for eleven more hours ([opus/interpretation](lineage-review/opus/interpretation.md#3-diagnosis-timeline) row 11). The same shape appears in the thresholds, each answering the latest complaint at the nearest module ([opus/player-response](lineage-review/opus/player-response.md#6-hard-thresholds-origin-and-fate) section 6), and in the evaluators ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F3).

Where the evidence narrows it: (i) the repository's triage skill tells the agent to prefer fail-fast slices and leave direction to the human, and the human steered about fourteen times a day, so "the agent did not revisit upstream assumptions" is partly what the instructions asked for ([opus/interpretation](lineage-review/opus/interpretation.md#8-method-problem-or-instructions) section 8; [H9](lineage-review/synthesis.md#h9)); (ii) the agent did recognise upstream questions and sometimes settled them (the expert question, the transfer audit, the ownership reversal, the sampling audit, the clean recipe; [astra/08](lineage-review/astra/08-codex-interpretation.md) Q3 and Q7), so the sharper failure is the gap between recognising a question and settling it before the next step, not blindness to the upstream; (iii) the two reviewers name different causes, under-training in one, the priority gap in the other, and neither count is reproducible from the record. The main thread's wording "instead of revisiting the upstream assumption" is supported in direction and should be read with (i) and (ii).

Proposed check: a **question ledger** in every brief and report. Each open question recognised in a note or report gets a row: settled (with the artifact), scheduled (named experiment and when), or parked by the human. A repair at the module nearest a symptom requires a ledger row naming the upstream alternative and why it is deferred. The mechanical part is a counter the main thread keeps over `ens watch` and the commit list: three consecutive repairs inside one package without a ledger row stop the job and escalate to the human, who owns direction unless H9 changes that. Run by the brief template and the main thread's review.

Cost, and what it cannot catch: it is a process rule; the review itself could not reconstruct these counts after the fact, so the ledger must be kept at the time or not at all; it says nothing about which upstream alternative is right; and if the human keeps direction, the check can only escalate, not redirect.

## 5. The agent as its own evaluator

<a id="fm-self-evaluation"></a>**Failure mode, replicated, 2026-10-02.** The agent's reading of rendered pages served as the evaluator; each instrument was added after a complaint and calibrated on the failure that triggered it; a development panel of a few TRAIN songs was reused for selection across dozens of experiments; a selection objective was reported as the gain.

Observed ([s-eval-sensitivity](lineage-review/synthesis.md#s-eval-sensitivity)):

- On the 40 pages behind V68 the agent wrote that mixed TAP and LN "remain possible" where the human judged the LN still badly off; documents cite page counts and reading receipts as evidence; no agreement rate was ever measured ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F8, doc-claim plus the index, confidence medium). Expert 1's blind listening or play protocol was not adopted; the agent's Lens reading stood in ([opus/interpretation](lineage-review/opus/interpretation.md#5-the-two-expert-replies-and-what-became-of-them) section 5, and "human judgment as data" in section 6). Claims of 40 or 209 pages read are recorded claims, not reviewed coverage ([astra/07](lineage-review/astra/07-evaluation.md) Q8).
- Evaluator timeline by git: envelope after the long-jack report, temporal evaluation after V56, short-LN 80 ms after V68, the 40 ms version after that; each next human inspection found a mode the current battery missed ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F3; the "calibrated on the triggering failure" reading is the reviewer's). Measured sensitivity: on the twelve V68 charts the gates in force passed 7, the final battery still passes 5 (F1, checked-artifact).
- Panel: Zenithfall case directories in 40 of 101 experiment directories, the other four songs in 11 to 17; sources marked `split: train`; 20 distinct audio hashes across 17 directories by plan; "it would be incorrect to call the repeated development panel held out" ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F6; [astra/07](lineage-review/astra/07-evaluation.md) Q4, both checked-artifact).
- The planner's sustained-attack excess was both its selection cost and the reported gain (0.0275 to 0.0004); the lineage document says so itself; the human then rejected the output as rigid ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F5, doc-claim consistent with code).

Where the evidence narrows it: the evaluation code was careful and honest, no model was ever promoted, the blind-spot probe found its own evaluator's holes, and the human asked for complaint-driven red evals (index V73) ([opus/evaluation](lineage-review/opus/evaluation.md#6-judgment) section 6). The instruments are trustworthy as specific detectors with a measured false-alarm rate; they are not evidence that a model improved.

Proposed check: (1) the **frozen evaluator** and the frozen reference and failure splits ([evaluation-first, Part 2 item 1 and Part 1 item 1](evaluation-first.md#p-claim-integrity)); an evaluator added after a complaint carries its date and the charts it was tuned on, and is never scored on those charts. (2) The agent's reading of pages is labelled **agent reading** and never appears in a pass or fail column until its agreement rate with the human on a blind sample has been measured ([Part 1 item 6](evaluation-first.md#p-chart-eval)); the verifier rejects a report that uses page reads as a gate. (3) Every reported number states whether it was a training or selection objective, mechanically: the receipt lists the objectives, the evaluator hash lists the measures, and any number on both lists is printed as "objective", never as "gain". (4) Songs used for selection go into the ancestry manifest, and evaluation songs must be absent from every ancestor's selection set ([fm-name-drift](#fm-name-drift)).

Cost, and what it cannot catch: the agreement rate needs human judgments, how many is open ([H3](lineage-review/synthesis.md#h3)); a frozen evaluator can be wrong, which Part 1 item 4 (dose sensitivity, false-alarm rate) is for; nothing here catches a failure mode the failure set does not yet contain. Only the human does, and when that happens the new case goes into the held-out failure set, not into the calibration set.

## 6. Names that outlive what they denote

<a id="fm-name-drift"></a>**Failure mode, replicated and audited, 2026-10-02.** A name kept denoting the thing it was first given to after the thing had changed: "R1" for a decoder that had dropped four of R1's components; "held out" for a panel reused for selection; "pass" for predicates with different thresholds and boundaries.

Observed: after about three hours the joint model copied 2.44M of R1's parameters and dropped the seed residual, the landmark memory, `frontier2` and the look-ahead columns; later statements that "R1 prefers" something concern this descendant, and the final segment decoder removed the consequence path again ([s-lineage-r1-is-not-r1](lineage-review/synthesis.md#s-lineage-r1-is-not-r1); [opus/r1-foundation](lineage-review/opus/r1-foundation.md#2-findings) F8; [astra/08](lineage-review/astra/08-codex-interpretation.md) checked evidence A and section 10 item 1). The feedback index had to correct its own key-2 line for the same reason. "A pass means different things in different generations": strict HH under 20 ms, inclusive at most 20 ms, the 60/50/50 support and the 40 and 80 ms prevalence checks are not interchangeable, so earlier zero counts were numerically correct while the problem persisted ([astra/07](lineage-review/astra/07-evaluation.md) section 10 item 1). The development panel was called held out because the last fit omitted those songs ([astra/07](lineage-review/astra/07-evaluation.md) Q4).

Reading: the human's reset decision had to be made on sentences about "R1" that were about a different model; a reader cannot tell from the prose.

Proposed check: an **identity receipt**. Every model name in a report resolves to a checkpoint hash plus the list of module names present in it. A name from a tagged release may be reused only when that module list equals the release manifest's; otherwise the verifier requires a derived name (for example "R1-initialised decoder"). The comparison is mechanical and lives in the execution receipt ([fm-claimed-not-done](#fm-claimed-not-done)). "Held out" is defined as absent from every fit set and every selection set of every ancestor, checked against ancestry manifests that every run writes. "Pass" always names the evaluator hash and the threshold.

Cost, and what it cannot catch: ancestry manifests have to exist from the first run after the restart, which is cheap now and impossible retroactively; prose words whose meaning drifted ("ordinary", "response") are the formulation's job, not a receipt's ([s-response-undefined](lineage-review/synthesis.md#s-response-undefined)).

## 7. Advice adopted in name, not in substance

<a id="fm-advice-adopted-in-name"></a>**Failure mode, replicated in direction (two reviewers read both replies), 2026-10-02.** A conditional recommendation from an expert or the human was recorded as adopted, its first step was done, and its condition was then ignored.

Observed: expert 1 advised to widen paired-song coverage with the model unchanged and, if the larger data was still underfit, to keep increasing coverage and training, and not to read non-convergence at equal updates as "more data does not help"; the budget-matched run was done within hours, its curve was still improving, and it was not continued ([opus/interpretation](lineage-review/opus/interpretation.md#5-the-two-expert-replies-and-what-became-of-them) section 5, which calls this "ignored in substance"; [astra/08](lineage-review/astra/08-codex-interpretation.md) Q5: "partly adopted; no convergence-controlled data-scaling result found"). The blind listening protocol was not adopted; expert 2's current-policy state coverage was acknowledged and not completed; the strong H isolation comparison was never run. From the human's side: the instruction against hard-coded rules produced a support that allowed 1 ms holds, and a 20 ms example of badness became a threshold ([H8](lineage-review/synthesis.md#h8); [opus/player-response](lineage-review/opus/player-response.md#6-hard-thresholds-origin-and-fate) section 6).

Where the evidence narrows it: the agent tested the replies rather than obeying them, and in the feedback ablation it rightly rejected an expert counterexample that did not apply ([astra/08](lineage-review/astra/08-codex-interpretation.md) section 4, Q8 item 2). The expert's question had also been framed by the agent so that the answer favoured the design already chosen (section 5 of the Opus report). The failure is bookkeeping of conditions, not deference.

Proposed check: an **advice ledger**, pasted into every brief: one row per recommendation from an expert or the human, as a neutral paraphrase, with its condition, its status (adopted, partly, not, rejected with reason) and the artifact that shows the status. Before writing the next brief the main thread reads the ledger and flags every conditional recommendation whose condition held (for example "the curve is still improving") and was not followed. Run by the brief template and the main thread; the worker only fills the artifact column.

Cost, and what it cannot catch: process only; it cannot judge whether the advice was right; it depends on the main thread reading the curves rather than the worker's summary of them.

## 8. Promotion margins below the noise floor

<a id="fm-margin-below-noise"></a>**Failure mode, replicated, 2026-10-02.** Criteria for promotion and non-regression were declared tighter than the measured seed noise, single-pair effects were read as results, and no claim about a recipe or architecture had a repeat-training variance.

Observed: per-chart seed spread about 0.20 star from 24 same-arm pairs; one experiment's non-regression allowance of 0.10 star on a four-case mean whose standard error is about 0.10, which would fail often between two identical models; bootstrap intervals in one of the 65 lineage documents against thirteen of the baseline era ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F6, checked-artifact). In the one case where sixteen fresh seeds were drawn, a single-pair LN effect of -0.35 shrank to -0.04 with an interval spanning zero ([astra/07](lineage-review/astra/07-evaluation.md) Q4; [audit](lineage-review/fable/synthesis-audit.md) O5). "No independent repeat-training variance was established for any causal quality conclusion"; multiple generation seeds measure sampling variation, not training variance ([astra/08](lineage-review/astra/08-codex-interpretation.md) measurement ledger).

Where the evidence narrows it: the agent never promoted a model, the declared criteria mostly failed by margins larger than the noise, and the sixteen-seed retraction was the agent's own ([opus/evaluation](lineage-review/opus/evaluation.md#4-findings) F6; [astra/07](lineage-review/astra/07-evaluation.md) section 6). The hazard is in the declared criteria and in single-pair stories, not in a recorded false promotion.

Proposed check: **noise floor before criteria**. The first run after any evaluator change measures seed (sampling) and song spread on the baseline rows; every criterion is then stated as a multiple of that spread, in the brief. The frozen evaluator's report format prints the spread column and prints a difference below two standard errors as "none" ([evaluation-first, Part 1 item 5](evaluation-first.md#p-chart-eval)); the verifier recomputes from raw files. A claim about a recipe or an architecture needs at least two training seeds or carries the label "one training seed" in its claim line.

Cost, and what it cannot catch: sampling seeds are cheap, training seeds double a fit; a noise floor measured on the baseline may not transfer to another model's spread, so the spread column is per table, not a constant.

<a id="standing-rules-for-briefs"></a>
## Standing rules for briefs

A main thread copies these into every Astra or subagent brief. Each is one line and cites the failure mode it answers.

1. Before the run, state the claim, the metric, the threshold, the songs, the seeds and the stop rule; after it, judge the claim against that statement and label any other number post-hoc ([fm-preconditions](#fm-preconditions), [fm-margin-below-noise](#fm-margin-below-noise)).
2. Every output carries an execution receipt (entry point, session class, components instantiated with config, checkpoint hash, resolved config, seed, output hash); a report that names an output without a receipt is not read ([fm-claimed-not-done](#fm-claimed-not-done)).
3. Call a component "in the system" only if the receipt of the output you cite lists it; the demo path writes the same receipt and keeps the chart ([fm-claimed-not-done](#fm-claimed-not-done)).
4. Every claim names the test or evaluator run that fails if it is false; mechanism tests are engineering, not evidence; every model forward has an input-lesion test per named input ([fm-tests-not-binding](#fm-tests-not-binding)).
5. Draw no conclusion about architecture, initialisation or direction from a run below its stop rule; report it as "endpoint rejected at budget"; a structural finding cites the code line ([fm-preconditions](#fm-preconditions)).
6. Every table carries the baseline rows (held-out ranked, R1 with real times) and the seed and song spread; a difference under two standard errors is "none" ([fm-margin-below-noise](#fm-margin-below-noise)).
7. The evaluator is frozen and hashed; do not edit it inside an experiment job; never score an evaluator on the charts it was tuned on; page reads are "agent reading", never a gate; a number that was an objective is printed as "objective", never as "gain" ([fm-self-evaluation](#fm-self-evaluation)).
8. Every model name resolves to a checkpoint hash and module list; reuse a release name only with the release's module set; "held out" means absent from every ancestor's fit and selection sets ([fm-name-drift](#fm-name-drift)).
9. Keep the question ledger: each recognised question is settled, scheduled, or parked by the human; after three repairs in one module without a ledger row, stop and report ([fm-local-repair](#fm-local-repair)).
10. Keep the advice ledger: each recommendation's condition, status and artifact; flag a conditional whose condition held and was not followed ([fm-advice-adopted-in-name](#fm-advice-adopted-in-name)).
