## 2. Alternative complete systems

All warm-start from 56M (`load_warm_start` already permits only new zero-initialised reader weights to be absent, DEVIATIONS 11). Costs are Mac hours; "eval" is the §3 panel (~0.6 h per system with two sampling processes).

### S1. Self-anchor (SA): cumulative sufficient statistics + history dropout
- **Delta.** Inputs: ~14 shared query channels computed causally from committed rows: log1p(k), cum heads/row, cum LN share, cum jack rate (`cum_repeat/cum_heads`), cum held share, cum c3 and c4 rates, lane-head histogram (4, in hand order so the view stays equivariant), cum median log2 hold length so far, all zero at k = 0. Module: `anchor_reader = Linear(ANCHOR_DIM, H, bias=False)`, zero-initialised, added to the first query layer exactly like `ln_level_reader`. Objective: unchanged CE. Recipe: **history dropout**: on a fraction p = 0.5 of training windows, the encoded history is truncated to the last L ∈ {64, 128} rows (the TCN cache already supports `truncated_start`), so the anchor channels become the only source of the chart's level there and CE must read them. Sampling: full history, anchor from `chart.derived()` at each step (already computed).
- **Lifts** #1/#2 (a convergent estimator now exists on the natural path) and the identifiability half of #4. **Fixes F2** (mechanism: the response weight moves from the 64-row window share, which drifts, to the cumulative share, which moves O(1/k)). Does **not** fix F1: it locks in whatever the first 64-192 rows drew. Partial on absorption (an absorbing stretch raises the cumulative statistic slowly, so the anchor pulls back).
- **Cost.** 8 M exposures ≈ 1.25 h (+ ~0.1 h for the per-row cumulative arrays, which `derive` already loops over) + 0.6 h eval.
- **Touches.** `features.py` (`Derived` + 4 cumulative arrays; `query_features` ANCHOR_DIM; constant), `model.py` (`R2Config.self_anchor`, `history_dropout`, reader, `hands`, `window_hands` truncation), `train_ce.py` (config keys, a checkpointed RNG like `ln_level_rng`), `sampling.py` (pass-through), tests in `tests/r2/`.
- **Main risk / early sign.** The reader stays near zero because on real data the channel is redundant with the window (Fable add. 2). Early sign at the 2 M checkpoint: `anchor_reader` weight norm not growing, and own-prefix β_cum (the `model_cum2.py` regression) still ≤ 0.3. The real-prefix β is **not** a valid gate.
- **Controls later.** Each channel is a coordinate: at generation, feeding a *target* value in place of the running statistic is a request ("behave as a chart that has been at level x"). Playable by construction only in the range the corpus covers. Section regeneration: the anchor is the prefix's own statistics, which is what a mapper wants kept.

### S2. Explicit chart organisation θ with a prior (Θ)
- **Delta.** Generalise the existing `ln_level`/`ln_length` input (which is the 2-coordinate version of this) to a θ vector per chart: band one-hot, whole-chart heads/row, c3, c4, jack rate, held share, LN share, median log2 LN length, lane-mask entropy, loop rate, hand balance (≈ 14 channels + known bit), standardised. Module: `theta_reader` zero-initialised, same path as `ln_level_reader`. Objective: CE unchanged. Recipe: 30 % of windows get θ = unknown (existing dropout RNG). Generation: θ drawn **once** from an empirical prior conditioned on band × skeleton-density tercile (the `ln-level-prior-v2` machinery, extended so one empirical draw supplies the whole vector jointly and keeps its correlations), held through EOS; oracle mode as the ceiling.
- **Lifts** #3 (chart identity exists at BOS) and, if obeyed, makes #1/#2 unnecessary for the coordinates in θ: given θ the data's conditional is short-range, so reading its own window no longer drifts the level. **Fixes F1** (draw once from a band-conditioned prior; variety restored by construction) and **F2** on θ's coordinates (a constant input is a convergent anchor). CE will use it because it predicts strictly better than the window on real data (R² 0.65 vs 0.53 for LN share), so the identifiability risk of S1 is absent.
- **Cost.** θ computation over the cache ≈ 0.2 h (one pass; `ln_level.py` pattern), 8 M exposures ≈ 1.25 h, eval 0.6 h × {prior, oracle} but prior is the product mode; oracle can run on half the panel (≈ 0.9 h total eval).
- **Touches.** `ln_level.py` → `theta.py` (whole-chart stats, prior fit/draw), `features.query_features` (THETA_DIM), `model.py` (reader, `R2Config.theta`), `data.Corpus.source_theta`, `train_ce.next_batch`, `sampling.continue_chart(theta=...)`, `generate.py` CLI, `evaluate.py` oracle/unknown/prior panels (all mirror existing ln_level code paths).
- **Main risk / early sign.** Obedience in free runs: the model treats θ as a weak prior and still re-reads its own window, so prior-drawn charts land near the corpus mean anyway. Early sign at 2-4 M: oracle-θ BOS free runs' identity correlation with the source < 0.6 at rows 512+ (56M prefix-fade reaches 0.35-0.50), or the obedience slope of realised vs requested θ < 0.6. Second risk: the prior over-smooths (joint empirical draws fix most of this).
- **Controls later.** This is the most direct route: **every planned control is a coordinate of θ** (LN share and length already are; difficulty = band/star coordinate; the five style concepts become coordinates when labels exist). Obedience is scored on whole-song free runs. Practice-targeted generation = a requested θ; section regeneration = θ inferred from the surrounding chart (its realised statistics) and held.

### S3. Plan-then-realise (PR): a causal section planner over block θ plus a block-conditioned realiser
- **Delta.** Two modules. *Realiser*: S2's model, but the reader input is θ_b of the **current 64-row block** (from the source in training; dropout 30 %), so it learns p*(a_k | s_k, θ_block). *Planner*: a small GRU/MLP (≈ 50-100 k parameters) over blocks: input = the whole skeleton's block summaries (density, gap stats, bpm, position; the skeleton is given, so reading all of it is causal in song time), the realised θ of previous blocks, and a chart-level latent θ̄ drawn from a prior (S2's) → a Gaussian/mixture over θ_{b+1}. Trained by NLL on fit_train block sequences (12.6 M rows ≈ 197 k blocks). Generation: draw θ̄, then per block plan θ_b from the committed chart's realised previous blocks (feedback), realise 64 rows, repeat.
- **Lifts** #3, #8 (whole-song structure lives in the planner), and part of #9 (sections that end: the planner learns real block-to-block dynamics, including mean reversion to θ̄, which runs lack: held-share lag-2 autocorrelation 0.26-0.37 vs −0.04). **Fixes F1** (θ̄ and θ_1 drawn from the prior), **F2** (θ̄ is an explicit held state; excursions are planned and end), and gives the expressive-section behaviour the product wants.
- **Cost.** Realiser 8 M ≈ 1.25 h; planner ≈ 0.2 h; block-θ tables 0.2 h; eval 0.6 h (planner adds ~2 % to sampling). ≈ 2.3 h.
- **Touches.** Everything S2 touches, plus `theta.py` block tables keyed by (sha, block), `plan.py` (new: planner model, training, sampling), `sampling.continue_chart` (per-block θ schedule; the per-k input is a step function), `generate.py`.
- **Main risk / early sign.** Two-stage error: the realiser's block obedience is weak (sign: oracle-block-θ runs reproduce block nh/held with slope < 0.6 at 4 M), or the planner's sampled θ sequences drift themselves (sign: planner-only rollouts' first-to-last-third correlation < 0.7 while sources hold 0.80-0.91; this check costs minutes and needs no realiser).
- **Controls later.** The plan **is** the control surface: a mapper edits θ_b for one section (local-edit scenario), a practice target pins coordinates, ambient play uses the prior. Controls stay playable if the planner's support is the corpus's.

### S4. On-policy layer (OP): preference optimisation on the model's own continuations
- **Delta.** A recipe layer on top of S1-S3 or the baseline, not a new network. Pairs: from a shared real prefix (first third of ~350 long fit_train charts), sample two 512-row continuations; the preferred branch is the one whose block-Φ trajectory stays nearer the prefix's own identity and has fewer degenerate windows (q from a logistic of the measure difference); `train_dpo.py` (`sequence_log_prob`, β 0.1, λ_CE 0.2 on real anchor windows) exists and expects exactly this pair schema. The loader refuses `meta.source == synthetic`; these are self-play pairs under a new source tag, which is a human decision.
- **Lifts** #4 (the only system that puts gradient on own-history behaviour) and #5 indirectly. **Fixes absorption and residual F2** that S1-S3 leave; it is also the only way a *control* can be made to hold in rollout rather than teacher-forced.
- **Cost.** Pair generation 350 × 2 × 512 rows ≈ 0.36 M decisions ≈ 0.4 h with two processes; DPO ≈ 4× CE cost per scored decision (policy + reference, two branches) → 1 h ≈ 1.6 M scored decisions ≈ 1,500 pair passes (≈ 4 passes over 350 pairs; regenerate pairs each pass: ≈ 2.5 h for 3 rounds) + eval 0.6 h.
- **Touches.** New pair builder (`pairs.py`: sampling from prefixes, labeller from the collapse measures), `train_dpo.load_pairs` source policy, nothing in the model.
- **Main risk / early sign.** Reward hacking of unvalidated measures (X0 has not calibrated them yet) and KL drift: sign = fit_dev natural NLL up > 0.02 nats, or preference accuracy → 0.9 while the panel's identity correlation does not move. Do not run before X0 lands.
- **Controls later.** Obedience pairs (requested vs realised θ) are the same mechanism; this layer is how controls become effective on whole songs.

### S5. Long-context memory with pressure to use it (LM)
- **Delta.** Flip `memory: landmarks` (modules exist in the 56M checkpoint, `lm_out` zero-initialised, so the warm start is exact), add the S1 cumulative statistics as extra landmark key/value features, and apply S1's history dropout so CE must read the landmarks. Objective unchanged.
- **Lifts** #1 partly (attention over 64-row landmarks can approximate a running mean; the learned statistic replaces S1's hand-chosen one). Does not fix F1.
- **Cost.** 8 M ≈ 1.4 h (landmark attention adds ~10 %), eval 0.6 h. **Touches.** `train_ce` config, `model.read_landmarks` (feature concat), `window_hands`/`sampling` (marks already built).
- **Risk / sign.** v1 found the readout unused; with dropout it may still prefer the truncated window. Sign: `lm_out` norm flat at 2 M. Verdict: strictly dominated by S1 for the first round (same mechanism, more moving parts); run only if S1 passes and we want learned rather than hand-chosen statistics.
- Row head (rank 25 / autoregressive lanes): an ablation inside any passing system, not a system (table #7).

## 3. Bake-off protocol

**Panel (shared, frozen before the night).** The brief's "K ≥ 1,500, 25 per band" is not available in fit_dev: by band, K ≥ 1,500 gives 4 / 34 / 120 / 92 charts (bands 2-5; the cache has no band 6). Use **band 2: K ≥ 1,000 (47 charts), bands 3-5: K ≥ 1,500**; 25 charts per band, fixed by seed, excluding X0's items; 3 seeds (954-956). Median K ≈ 1,400 (band 2) to ≈ 2,100 (bands 3-5), so one system's BOS panel is ≈ 0.57 M decisions ≈ 0.35 h with two sampling processes; the prefix-mode panel (continue from the first third) ≈ 0.25 h.

**Two modes per system.** (a) BOS free run: tests F1 + F2 together. (b) Real-prefix continuation from the first third: tests F2 alone (F1 held fixed). θ-systems report prior mode as the product and oracle mode as the ceiling.

**Metrics (the agreed collapse measures).** Primary P1: identity hold = correlation across charts of run vs source whole-chart nh and held share at rows 1k+ in prefix mode (sources 0.78-0.92; 48M 0.35). P2: stay rate of degenerate stretches (`bus4`, 4-chord, loop; sources 0.24; 56M 0.53-0.57) and `bus4`-exit rate in band 2 (sources 1.3 %; 56M 16-31 %). P3: between-chart SD ratio per band for nh, c3, c4, held (variety; 56M 0.41-0.80). P4: first-to-last-third correlation within runs in BOS mode (sources 0.80-0.91). F3 diagnostic: adjacent-row dependence gap. Gates: legality 100 %, guards (i), (iii), (iv) v2, fit_dev natural-manifest NLL ≤ baseline + 0.02 nats. Human screen: X0's calibrated measure replaces P1/P2 as primary once it exists (AUC ≥ 0.75); until then, a blind screen of 2 BOS charts per system per band using the X0 harness.

**Single decision rule.** A system **wins the round** if it passes every gate and leads the rank-sum of P1, P2, P3 by more than 2 seed-SDs over the next system; any system within 2 SDs of the fine-tune control C has **not** fixed the defect. Ties go to the cheaper and more control-friendly system (Θ-type over SA-type).

**Equal budgets.** Every trained arm: 56M warm start, 8 M exposures, same lr schedule (200 k warm-up to 1e-4, cosine to 3e-5, i.e. `ce_v2_n_lnlevel_ft.json`'s), checkpoints at 2/4/6/8 M, same draw seeds, panel on the final checkpoint plus the P1/P2 early signs at 2 and 4 M (prefix mode on 8 charts, ≈ 5 min).

**Controls.** Baseline 56M (no training; eval only). **C = fine-tune-only** (56M + 8 M CE, no new input, same schedule): separates "more fine-tuning / a lower lr" from the change. For Θ-systems, **unknown mode** of the same checkpoint (θ dropped) is a second internal control: the gain must appear only when θ is supplied.

## 4. First bake-off (one night, ≈ 7.5 Mac hours)

**Arms.** Baseline 56M, C (fine-tune-only), **S1 SA**, **S2 Θ** (prior + oracle). Training sequential: C 1.25 h, SA 1.35 h, Θ 1.45 h (incl. θ tables) = 4.05 h; evaluation 0.6 h × 3 + 0.9 h (Θ two modes) = 2.7 h, two sampling processes, overlappable with the next arm's training on spare cores. Total ≈ 6.5-7.5 h.

**Why these.** SA and Θ are the two mechanistically opposite answers to Q1 and Q2: *can CE be made to read a convergent statistic of the model's own past* (SA, no external input, locks F1 in) versus *does a held external θ fix identity, and does a drawn θ restore variety without obedience failure* (Θ, fixes F1 and F2 for its coordinates, needs a prior). They share one code path (a zero-initialised reader on the first query layer), so the comparison is fair and the implementation delta is small; C separates both from the schedule; S3 and S4 build on whichever wins, so they are round two. S5 is dominated by SA for a first test. S4 must wait for X0 (its reward is the measure).

**Expected outcomes and what each means.**
- Θ oracle P1 ≥ 0.7 and prior P3 → 0.9-1.0 with band-2 `bus4` exits < 5 %, SA within 2 SD of C: identity must be imposed, not inferred. Round two: **S3 plan-then-realise vs Θ + S4**, and the controls become θ coordinates immediately (LN level/length first, since the data exist).
- SA P1 ≥ 0.7 and own-prefix β_cum ≥ 0.4, Θ prior fails on P3 or oracle fails on P1: the model can hold its own past but will not obey an external level. Round two: SA + band input (F1), then S4 for absorption; controls route through the running-statistic coordinate (S1's "target in place of statistic").
- Both pass: combine (θ at BOS + running anchor; one model) and move to S3 for sections and S4 for obedience; the row-head ablation rides along.
- Both within 2 SD of C, and C within 2 SD of baseline: CE will not teach any input to override the window on own histories (Fable add. 2's fallback). Round two is **S4 on-policy on the baseline vs on Θ**, pairs labelled by the X0-validated measure, with decode-time conditioning on the running statistic as a no-training control.
- C beats baseline by > 2 SD: the lower-lr continuation itself moved the regime (D8's flips); re-run selection on the collapse panel before any architecture claim.

**Evaluation changes that cost nothing and apply from this night:** panels of long charts per band as above, selection on P1/P2 rather than NLL + short-chart guards, and the 2 M / 4 M early signs so a failing arm can be killed and its slot given to S5 or the row-head ablation.
